untofu

Open a document built with fonts you don't have and macOS quietly swaps in something else, then asks which replacements you'd like. untofu answers the request instead: it finds the font, fetches it, and hands it to the application that asked.

Tofu is the typographer's word for □, the blank box a renderer draws when it has nothing to set a character in. macOS doesn't literally draw tofu for a missing font — it substitutes something else and asks you to pick a replacement — but it's the same failure in a politer suit. The icon is that box with a real letter standing in it.

Free and open source under the MIT licence. Fetches only openly-licensed families from Google Fonts; it will not obtain a commercial font for you, and does not try to.

The dialog

Every so often a document arrives that was set in a font your Mac has never seen. Keynote, Pages and PowerPoint all handle it the same way: substitute something roughly the right shape, then offer you a list and ask which replacement you would like. The layout has already moved by the time you see it.

The awkward part is that a great many of those fonts are free. Raleway, Lora, Karla, Rubik and around eighteen hundred other families are openly licensed and a few hundred kilobytes away. The dialog doesn't mention that. It just asks you to pick something else.

What it does instead

macOS has a system-wide hook that fires whenever any application asks for a font it can't resolve. untofu listens on it. When the request is for a family it can obtain, it fetches the font and hands the file straight back to the asking application — no installer, no Font Book, no dialog.

  • Cached first, always. The hook runs with the asking app's text layout blocked behind it, so a font already cached is a dictionary lookup and nothing else. Nothing on the network happens there.
  • One download covers the family. Fetching one weight indexes every face in the file. Asking for Raleway indexes eighteen names.
  • It verifies before it caches. A downloaded file has to actually answer to the exact name that was requested. A family-name match is not good enough, and getting this wrong fails silently.
  • It says so when it can't. If a font isn't obtainable you get told which one, why, and where to look for it.

Because the fetch happens in the background, the document that triggered it has already drawn itself with a substitute. Reopen it and the real font is there. Everything after that is instant.

Where it works

Each of these was checked by building a document against a font, removing that font from the machine, and opening the document with untofu running.

Adobe AcrobatnoResolves fonts internally, never asks the system

Acrobat is the one real gap. It has its own font engine and its own substitution, and never consults macOS at all — which is presumably why Adobe built font activation into their applications rather than relying on the system. Inside Acrobat, use Adobe Fonts.

Browsers are deliberately left alone

Web pages reach the same hook, and untofu declines them. A font already in the cache is still handed over — that costs nothing — but a browser never triggers a download and never raises a dialog.

The reason is a CSS rule of the form src: local("Product Sans"), url(…), which sites use to say “use the visitor's copy if they have one, otherwise download it”. That local() is a by-name lookup, so on a Chromium browser every such site asks your Mac for a font by name — and the page renders perfectly without it, because the url() is right there.

This one is about privacy, not tidiness

Every font a page asks for and untofu can't find would otherwise become a request to GitHub. Fetching on behalf of a browser would quietly leak the shape of your browsing to a third party, so it is off by default rather than as a matter of preference. --fetch-for-browsers turns it on if you want it.

What it won't do

It can't get you a commercial font

untofu fetches from the openly-licensed Google Fonts catalogue and nothing else. If a document wants a licensed typeface, no tool should quietly go and get it for you, and this one doesn't. It tells you what's missing and points at Adobe Fonts, MyFonts, Fontspring and WhatTheFont so you can sort out a licence yourself.

Apple may remove the hook it depends on

The system hook untofu uses has been marked deprecated since macOS 11, with a note saying it will be removed in a future release. It still works on macOS 26, fifteen releases later, but that removal is the expected end of this tool's life. If it happens, untofu exits with a clear message and missing fonts behave exactly as they did before it was installed. Nothing breaks; it just stops helping.

It also stays out of the way of fonts it knows it can never supply. Opening any PowerPoint file asks for Calibri, Aptos and Segoe UI; those are declined in about ten milliseconds, without a network request and without bothering you about fonts you can do nothing about.

How it works

The hook is CTFontManagerCreateFontRequestRunLoopSource, a CoreText facility that hands your process the font requests of every other process, along with the PostScript name being asked for. Return a file and the system issues a sandbox extension for it to the requesting application — which is what allows a sandboxed app like Keynote to read a font file it was never granted access to.

The whole thing is a background launchd agent. There is no window, no menu bar item and nothing in the Dock. It is invisible until it has something to say. The README documents the undocumented parts, including the return type the headers don't specify and the crash you get for guessing wrong.

Already have a font manager? RightFont, Typeface and FontBase all auto-activate fonts from a library you already own. untofu solves the other half — the font you don't have yet — and is happy to sit alongside them.
